# Changes

What changed in each version of labspec-translator (ls6t), newest first. Versions follow the date: YYYY.MM.DD.N, N counting the releases of that day. The version is set in one place, `labspec_translator/__init__.py`; `ls6t --version` prints it.

| Version | Changes |
|---|---|
| 2026.11.25.12 | **An unreliable calibration stores nothing**, whatever made it unreliable (multimode points, a laser-line jump, an outlier, a stop), not only unsettled repeats: the correction is stored only once the whole study is judged reliable; otherwise `stored_as` says "nothing stored: the calibration is unreliable (…); the correction in use stays" and `outcome` "NOT stored" (run 152541: both studies were unreliable and both corrections became active). **profile_problems cleared once fixed**: `profile set` saved the load-time `problems` list into the profile file, so the next load still reported a value the set had just fixed; `problems` is never saved now and is dropped from files that carry it. The profile is read afresh for every request (no cache). |
| 2026.11.25.11 | **Flat tools answer within 90 s** (`LS6T_FLAT_WAIT_S`): `measure_spectrum` / `calibrate_si` start the request detached, as `run_studies`, and return its request to poll with `study_status` if it has not finished (a client link gave up at 140 s). The request records how its runner was started (`runner_started`); an interrupted one whose runner ran inside the app's job says it ended with the MCP server. **A dead runner's lock no longer blocks the instrument**: only the request holding the lock refreshes it (a queued request's own heartbeat kept a dead runner's lock fresh, so every later request queued forever); a holder whose state is final or whose runner has been silent for 90 s is passed over; an interrupted request frees the lock as soon as it is found interrupted, and `cancel` frees it (`lock_released`). **Waiting for the operator is said**: while a request waits for the go-ahead (or any question) in LabSpec, `study_status` gives `waiting_for` ("the operator's go-ahead in LabSpec (… s so far): …") and `next` tells the model to tell the user; the flat tools' progress messages say the same. **The stale-correction warning** takes the repositioning from the profile's (or measured) repeatability for that grating, not a fixed "±1 cm⁻¹ at 600". From run 151438: **a live runner is never called interrupted**: the runner has a heartbeat thread of its own (every 10 s, whatever it is doing), and a request is declared interrupted only when its heartbeat and runner.log are both older than 90 s and its process is gone (checked by pid; Windows: OpenProcess, never a kill); a stale lock is judged the same way, and `jobs` flags one (`instrument_lock_stale`). **`instrument laser_off` during a request cancels that request** (`cancelled_request`), so it cannot hold the shutter open again (the hold lost "before laser" in g600_labspec was a `laser` command, i.e. a laser_off/on from outside the request, not LabSpec's multi-window placement). **Calibration repeats that did not settle (a step or a creep) store nothing**: the correction in use stays, `stored_as` "nothing stored", the study unreliable (the hop 7.78, 7.13, -0.95, -0.51, -0.00 had stored its median -0.004). **A laser line more than 3 cm⁻¹ from the calibration's makes the result unreliable** ("another mode: a hop or multimode"), as does "zero uncertain" at more than a tenth of the spectra. |
| 2026.11.25.10 | **Every request failed on its first acquisition** (`AttributeError: 'str' object has no attribute 'get'`): `spectrometer.repeatability` set from Windows PowerShell lost its inner double quotes, `profile set` stored the text, and the zero's repeatability lookup read it. **`profile set` never stores JSON as text**: a value starting with `{`/`[` (or for a key that holds a group or a list) that is not JSON has its quotes put back (`repaired`, check `new`) or is refused with how to quote in PowerShell; `profile set KEY @file.json` reads the value from a file; a group cannot be replaced by a number or text. **The profile is checked on load**: a group stored as text is read as JSON if it is, else ignored (the default is used) and listed as `profile_problems` (in `run_studies`' answer and the request's state); a repeatability entry that is not `{moved_sd_cm1, still_sd_cm1}` is ignored. **On any runner failure the shutter hold is released first**: the runner waits (up to 90 s) for a busy bridge and sends `safe` (closes the shutter, releases the hold), else leaves `safe` queued for the bridge (it runs before anything else); the state says `shutter_hold_released`. **A runner fault no longer blames the bridge**: "ls6t failed (its own fault, not the bridge's or LabSpec's)" with the `trace` in `study_status`, and "the laser shutter is closed" once released. **A bridge that stops answering while the hold is on is re-checked**: ls6t waits for it to answer again, releases the hold and says the shutter is closed (LabSpec was only held up: no restart); only when it never answers does the laser warning stay, with `safe` queued. **The first acquisition after a grating change** no longer looks like a stuck bridge: the bridge announces its spectrometer jog, approach and native-map approach moves as blocking (they were silent, longer than the 20 s heartbeat limit). **Measure-only tools keep `instrument laser_off`** (it only closes); the flat tools' answer says to call it if the hold could not be confirmed released. The ls6t skill replaced with Nicola's new version (measure_spectrum / calibrate_si). |
| 2026.11.25.9 | **For small local models** (a 4B model's `run_studies` calls never reached ls6t). **`measure_spectrum`** and **`calibrate_si`**: flat scalar arguments with defaults (laser_nm snapped to the instrument's nearest laser, 638 → 637.75; a centre or from/to; the objective by magnification, x100 → x100_VIS), they build the study, run it and wait up to ~5 min (progress kept alive), and answer in a few numbers (reliable, peaks, calibration, warnings) or with the request to poll. **`run_studies` / `validate_studies` accept the studies as JSON text**, and a single unnamed study; anything else gets a clear error. **Refused calls are logged** (`LS6T_HOME/rejected_log.jsonl`) and listed by `jobs` (`rejected_calls`). **A measure-only tool set** (`LS6T_TOOLS=measure`, `ls6t connect APP --tools measure`): the measurement, study and read-only tools; `instrument` answers status / last_error / resume only; no `set`, `laser_on`, `snapshot` or benchmarks. |
| 2026.11.25.8 | The ls6t skill for LM Studio Bionic updated (Nicola's new SKILL.md: rules first, exact `laser_nm` values per laser, translating the user's words into keys, one worked example, shorter recipes, what to do on errors). The installer and `ls6t connect bionic` replace the previous copy (backed up). |
| 2026.11.25.7 | **The ls6t skill for LM Studio Bionic**: the package carries `skills/ls6t/SKILL.md` (Agent Skills format: how to turn a request into studies, the defaults, recipes for a spectrum, a wide range, a Si calibration, a map and a series, polling and reporting); `ls6t connect bionic` and the installer's *LM Studio Bionic* option write it to `%USERPROFILE%\.lmstudio\skills\ls6t\SKILL.md`, where Bionic keeps a skill added in Settings > Skills (a different SKILL.md there is backed up first; nothing else in the folder is touched; Bionic's built-in skills under `apps\bionic\.internal\skills` are never touched). Uninstalling removes ls6t's SKILL.md, and the folder only if nothing else is in it. |
| 2026.11.25.6 | From the repeatability run (with the approach the repositioning adds ~0.15–0.2 cm⁻¹ at 600, 1200 and 1800). **The first spectrometer move after a grating change is always made, with the approach**: every acquisition of a study carries the approach (the discarded first spectrum too, which had made that move without it), and the first one after a grating change moves even when the spectrometer already reads the centre (`spectro_force`; LabSpec re-places it when the turret turns: 0.53 cm⁻¹ off at 1800). **Native map's `before_map_nm` is read after ls6t's last move** (it read the approach point, so every map looked moved by LabSpec). **Outliers among repeats**: off the others' mean by more than 6 × their SD (as a prediction) and 0.3 cm⁻¹, the worst first, at most one per five (9.597 among 8.90s was missed; ~4 % of 5-repeat noise sets, under 1 % from 8). **No drift reported against repeats from before 2026.11.25.1 or not settled** ("+1.39 since 23:38:43" was last night's step-contaminated entry). |
| 2026.11.25.5 | **Native maps**: ls6t pre-positions the spectrometer at the map's centre with its approach (`spectrometer.approach_nm`), then reads it when LabSpec's map has started and after it (`native_map.spectrometer`: `before_map_nm`, `read_during_after_nm`, `moved_by_labspec`). Unmoved, the approach-based repeatability applies to the map's zero; moved by LabSpec (or not read), the `@labspec` entry. |
| 2026.11.25.4 | `approach_nm` covers only ls6t's own spectrometer moves: windows LabSpec places itself (extended ranges, `range_placement: "labspec"`, its own maps) have their own repeatability entry, `"<laser>@<grating>@labspec"` (profile or measured by calibration repeats over such a range), and never take the approach-based spread; `correction_used.expected_uncertainty_from` says which. |
| 2026.11.25.3 | From the 600 gr/mm repositioning test: **backlash** — the repositioning spread was ~0.5 cm⁻¹ moved without an approach and ~0.15 with `approach_nm: -2` (still 0.26 against moved 0.40–0.59 / 0.30). **`spectrometer.approach_nm` is −2 by default** (every move ends from 2 nm below; 0 turns it off). **Repeatability per laser@grating**: `spectrometer.repeatability["<laser>@<grating>"]` in the profile (set by a person) wins over the last measured; a moved SD measured with another approach than the profile's no longer counts. **Pool decisions ignore entries whose repeats were judged before 2026.11.25.1, or not settled** (every 600 calibration found a "real window dependence" against an 11.35 entry that held a step; listed with `older_centres[].why`). **The repeats warning names the median** (the value stored), not the mean. **The jog and the approach have their own timing lines** (`t_spectro_jog_s`, `t_spectro_approach_s`), no longer "waiting for motors… a grating turret still turning?". |
| 2026.11.25.2 | The spectrometer's repositioning spread is not added to the calibration's pass tolerance (it judges the calibration itself); a corrected spectrum keeps `expected_uncertainty_cm1` and warns when it exceeds the Si tolerance (e.g. 600 gr/mm after a spectrometer move). |
| 2026.11.25.1 | From .20 on the instrument: the spectrometer repositions to about ±1 cm⁻¹ at 600 gr/mm (repeats moved away and back: SD 0.9–1.2; a held series without moves: 0.12), and that looks like a laser hop. **A jump after a spectrometer move is "a laser hop or the spectrometer repositioning"** (`checks.laser_line.jumps[].after_spectrometer_move`, `what`); only a jump without a move is called a laser hop. **Robust repeats**: the median is stored; an outlier (> 3 robust SDs and 0.3 cm⁻¹ from the median) is left out; a **step** between two runs (means over 5 × their pooled standard error) or a steady **creep** (slope over 5 × its standard error) makes the scatter "not noise" (not used to compare windows); replaces the slope-and-drop test, which kept the step of 10.01 → 12.33 and called it settled. **`calibration.repeats_move: false`** repeats without moving the spectrometer (noise alone); the SD with and without moves is kept per laser@grating (`spectro_repeatability.json`, the result's `repeatability`), and a correction used across moves reports `expected_uncertainty_cm1`. **`spectrometer.approach_nm`** (profile): every spectrometer move ends from the same side, to test backlash. **The first spectrum after a grating change is discarded** before calibration repeats (it was the outlier twice). Warnings say to measure at the calibrated centre in the same request at coarse gratings. |
| 2026.11.24.20 | Three details (Nicola). **Drop-leading floor**: at least 3, and at least half, of the repeats are kept; a trend that needs more dropped is reported "never settled" (its scatter not used). **The open wait applies only to a fresh opening** (a hold continued from the previous study waits nothing; confirmed, as before). **Every study, not only calibrations, waits 40 s after a fresh shutter opening for a laser marked `mode_hops` / `unstable_multi`** (`OPEN_SETTLE_DEFAULT_S`; a 5 × 5 map's laser line went −3.55 → −2.95 cm⁻¹ over its first ~30 s): `lasers.<k>.hold_open_s` overrides it for ordinary studies, `calibration_open_s` for calibrations (never under 40 s without it); `settle_s` no longer sets it. |
| 2026.11.24.19 | From .18 on the instrument (order, repeats with the SE test, time window, range corrections, DeNoise noise, header ICS pass). **Seams of stitched ranges found**: a one-step dip in the point spacing (1.56 → 1.12 → 1.60 cm⁻¹ at ~1945 cm⁻¹) was missed; now a step off the spacing's smooth trend counts, as well as a lasting change. **Drift during repeats**: a slope over 2 × its standard error is "drifting" (warned); the leading spectra are dropped until the rest is flat (`dropped_leading`, `settled`), and if it never settles its scatter is not used to compare windows (637.75 @ 600: 11.31, 10.00, 9.99, 9.58, 9.60 with the laser line moving in step). **A longer open wait before calibrations** for a laser marked `mode_hops` / `unstable_multi`: `lasers.<k>.calibration_open_s` (default 40 s; the zero still moved ~40 s after the shutter opened). **Stale corrections warned**: the laser line more than 0.5 cm⁻¹ from the calibration's (was 1.5), and a correction over 1 h old for a laser whose zero drifts; `correction_used` gives `age_h`, `range_match`, `range_cm1`, `pooled`, `repeats`. **Estimate breakdown consistent** (`first_acquisition`, `per_acquisition` for the rest, `acquisitions` their sum). An extended-range calibration says "kept for the range 100-3200 cm-1". |
| 2026.11.24.18 | `calibration.store: auto`, two details (Nicola). **The test compares the centre means by their standard errors**: pooled only when every two agree within 2 × √(SE₁² + SE₂²) (repeats 5, SD 0.5: ~0.63 cm⁻¹; 2 × SD, ~1.0, would have pooled a real 0.8 cm⁻¹ window difference). **Only entries from the same request, or within 1 h, are compared and pooled**: older ones would bring the day's drift in (637.75 @ 600 at 659.66 nm: −12.11 in the morning, −9.2 … −9.9 in the evening), either averaged into the pooled value or taken for a window dependence. When a window is calibrated again later, the result reports the drift there (`drift_at_centre`) and the older centres that still carry it (`older_centres`), with a warning to recalibrate them. |
| 2026.11.24.17 | **`calibration.store: auto` no longer pools by pixel size alone** (Nicola): 532 @ 1200 has a real window dependence (+4.05 / +2.18 / +1.80) at ~2.6 cm⁻¹ per pixel, and 637.75 @ 1200 sits on the old 2 cm⁻¹ threshold. Every calibration keeps its per-centre entry; one correction (the mean of the centres) is used for every window only when the centres differ by no more than 2 × the repeats' SD (`calibration.repeats`); without repeat data, only at ≥ 2 cm⁻¹ per pixel *and* with the centres within 1 cm⁻¹. The per-centre entries stay, so later evidence can undo the pooling; the result says which and why (`stored_as`, `stored_correction.pool`). |
| 2026.11.24.16 | From .15 on the instrument (read-back, `correction_used`, bad fits, grating retry, multimode exclusion pass). **Each spectrum's `t_start` is LabSpec's Acq**: the bridge reports `t_to_acq_s` (its time before Acq: the spectrometer move after a grating change, the flush, the settle) and series spacing counts from there (a 26 s and a 42 s spectrometer move had counted as point 0's in the first gap). **No contradiction on the laser-line drift**: the warning says "followed" only when a plateau's step was applied, else "not followed: under the step threshold". **The unprotected first exposure is warned at validation**: a laser marked `mode_hops` / `unstable_multi`, LabSpec opening the shutter for each spectrum, no `settle_s` and no warm-up (point 0's Si 8.2 against 6.1 cm⁻¹ with settle_s 0): hold the shutter (its open wait), give the laser its `settle_s`, or `acquire.warmup_s`. **Calibration repeats** (`calibration.repeats: N`): N spectra at the same spot, the spectrometer sent 3 nm away and back before each, so each lands on the pixels afresh; the correction is their mean, with `repeats {n, offsets_cm1, mean_cm1, sd_cm1, sem_cm1}` (at 600 gr/mm the same window repeated to ±0.5 cm⁻¹ while the fit's own error said 0.2). **Pooled corrections** (`calibration.store: auto | per_centre | pooled`; a calibration over the same range_cm1 is kept for that range and used for it (`range_match`); otherwise a warning that one window's correction was applied to a stitched spectrum. **Bogus spectrometer read-backs** (−2027 nm after a grating change) ignored (`spectro_reading_invalid`). **Estimate for the points engine**: one spectrometer move per study, held spectra with timing.held_overhead_s, the live view per point (a 5 × 5 map: 3.0 min estimated, 1.45 min measured). |
